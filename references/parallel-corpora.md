# Parallel corpora — ParaConc-style workflow from the CLI

ParaConc (Michael Barlow) is a Windows GUI for parallel-corpus concordancing. As of April 2026 it is no longer actively maintained. There is no MCP server for parallel corpora. The local-CLI workflow below replicates ParaConc's core capabilities.

## Where to get parallel data

### OPUS (Helsinki-NLP, Jörg Tiedemann)

The largest open collection of parallel corpora. https://opus.nlpl.eu and https://github.com/Helsinki-NLP/OPUS.

Install the CLI (the corpus-tools-skill `setup-python-env.sh --opus` does this):

```bash
uv pip install opustools opusfilter
```

Download a parallel corpus:

```bash
opus_get -s en -t cs -d Europarl -p moses -dl ./opus-data
```

`-s`/`-t` are the source/target language codes. `-d` is the corpus name. `-p moses` gives Moses format (one sentence per line, parallel files). `-dl` is the download directory.

Common OPUS corpora:

| Corpus | Domain | Languages |
|---|---|---|
| Europarl | Parliamentary debate | EU languages, sentence-aligned |
| OpenSubtitles | Film subtitles | 60+ languages, time-aligned |
| TED2020 | TED talks | 100+ languages |
| News-Commentary | News op-eds | 12 languages |
| WikiMatrix / CCMatrix | Mined web parallel | 1620 language pairs |
| ELRC-CSV | EU legal/admin texts | EU languages |

For a curated map: https://opus.nlpl.eu/

### Other sources

- **Europarl** directly: http://www.statmt.org/europarl/
- **Common Crawl Parallel Corpora**: https://commoncrawl.org/
- **Tatoeba**: small but high-quality sentence pairs across many languages

## Filtering and cleaning

Raw OPUS data is noisy — alignment errors, language-detection failures, length-ratio outliers. `opusfilter` is the standard cleanup tool:

```yaml
# opusfilter-config.yaml
common:
  output_directory: filtered

steps:
  - type: filter
    parameters:
      inputs: [en.txt, cs.txt]
      outputs: [en.clean.txt, cs.clean.txt]
      filters:
        - LanguageIDFilter: {languages: [en, cs]}
        - LengthRatioFilter: {threshold: 3}
        - LengthFilter: {min_length: 1, max_length: 100}
        - CharacterScoreFilter: {scripts: [Latin, Cyrillic]}
        - TerminalPunctuationFilter
```

```bash
opusfilter opusfilter-config.yaml
```

For deduplication (especially important for web-mined corpora):

```bash
# Sort, dedupe by line, then re-pair
paste en.txt cs.txt | sort -u | awk -F'\t' '{print $1 > "en.dedup.txt"; print $2 > "cs.dedup.txt"}'
```

## Aligning unaligned bitexts

If you have two texts (e.g. an English novel and a Czech translation) that aren't sentence-aligned:

1. Sentence-segment each side: spaCy or Stanza, output one sentence per line
2. Run `hunalign`:

   ```bash
   hunalign null.dic en.sentences.txt cs.sentences.txt -realign > alignment.txt
   ```

   `null.dic` is an empty file (or a real bilingual dictionary if available). `-realign` does a two-pass alignment (more accurate; a bit slower).

3. Filter by quality (the score in column 1 of `alignment.txt`); typical thresholds: keep alignments with score > 0.4

For modern alternatives: `vecalign` uses LASER sentence embeddings for higher-quality alignment but needs a GPU (or MPS) and is slower per pair.

## Encoding parallel corpora as CWB for CQP querying

Once you have aligned, cleaned bitexts, encode each side as a CWB corpus (per the main skill's `build-cwb-corpus.sh`), then add an alignment file:

```bash
# Encode EN side
cwb-encode -d $DATA/en -F vrt-en -R $REGISTRY/europarl-en \
  -P lemma -P pos -S s:0+id

# Encode CS side
cwb-encode -d $DATA/cs -F vrt-cs -R $REGISTRY/europarl-cs \
  -P lemma -P pos -S s:0+id

# Build alignment file (TSV: en-corpus en-region cs-corpus cs-region)
# ... typically generated by your alignment script
cwb-align-encode -D -R $REGISTRY/europarl-en-cs.align alignments.txt

cwb-make EUROPARL-EN
cwb-make EUROPARL-CS
```

Then query in `cqp`:

```cqp
EUROPARL-EN;
EUROPARL-EN> show +EUROPARL-CS;
EUROPARL-EN> [lemma="literally"];
EUROPARL-EN> cat;
```

Output shows each EN match alongside its aligned CS sentence — the ParaConc UX, but indexed and CQL-queryable.

## Quick parallel-concordance script (no CWB)

For a directory of paired files (e.g. `texts/en/file42.txt` and `texts/cs/file42.txt`), where each side has one sentence per line, this is the simplest concordance:

```python
from pathlib import Path
import re

en_dir, cs_dir = Path("texts/en"), Path("texts/cs")
query = re.compile(r"\bliterally\b", re.I)

for en_file in en_dir.rglob("*.txt"):
    cs_file = cs_dir / en_file.relative_to(en_dir)
    if not cs_file.exists():
        continue
    en_lines = en_file.read_text(encoding="utf-8").splitlines()
    cs_lines = cs_file.read_text(encoding="utf-8").splitlines()
    if len(en_lines) != len(cs_lines):
        continue  # alignment mismatch
    for en, cs in zip(en_lines, cs_lines):
        if query.search(en):
            print(f"EN: {en}")
            print(f"CS: {cs}")
            print()
```

This is the 20-line ParaConc replacement. For anything beyond this, encode with CWB.

## Comparison: tools for parallel-corpus work

| Need | Tool | Comment |
|---|---|---|
| Get parallel data | `opustools` | Helsinki-NLP standard |
| Filter parallel data | `opusfilter` | Same family |
| Sentence-align | `hunalign` (CLI) or `vecalign` (LASER) | hunalign for fast/CPU; vecalign for quality |
| Edit alignment by hand | `InterText` | Czech corpus team's GUI; web + desktop |
| Concordance one-shot | the 20-line script above | Fine for <1M pairs |
| Concordance at scale | CWB with `cwb-align-encode` | Indexed, fast, CQL queries |
| Translation memory output | `LF Aligner` | Outputs TMX |

## Why no MCP server (yet)

The Learning Log entry at `linguistics/agent-tools-for-linguists/` documents this gap. CWB has had parallel-corpus support since the early 2000s; the Yu et al. (2026) three-tool MCP architecture (`corpus_info`, `cqp_query`, `cqp_frequency`) is in principle extendable to it. As of April 2026, no public MCP server has been built for this case. A motivated user could write one — it would be a half-day project given the existing CWB infrastructure.
